# RemoPad Protocol v1

初版协议运行在 UDP/IPv4 上，默认端口为 `51234`。所有多字节字段均为 little-endian。

## 数据包头

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | magic | ASCII `RMP1` |
| 4 | 1 | version | 固定为 `1` |
| 5 | 1 | type | 消息类型 |
| 6 | 2 | payloadLength | 载荷长度 |
| 8 | 4 | sequence | 发送端递增序号 |
| 12 | 4 | pairingCode | 0 到 999999 的配对码 |

固定头长度为 16 字节。

## 消息类型

### `0x01` Pointer move

载荷长度 8 字节：

| 类型 | 字段 | 说明 |
|---|---|---|
| Float32 | dx | 水平相对移动量，向右为正 |
| Float32 | dy | 垂直相对移动量，向下为正 |

### `0x02` Scroll

载荷长度 8 字节：

| 类型 | 字段 | 说明 |
|---|---|---|
| Float32 | dx | 水平滚动增量 |
| Float32 | dy | 垂直滚动增量，手指向下为正 |

### `0x03` Button

载荷长度 4 字节：

| 类型 | 字段 | 说明 |
|---|---|---|
| UInt8 | button | `1` 左键，`2` 右键 |
| UInt8 | state | `0` 释放，`1` 按下 |
| UInt16 | reserved | 固定为 0 |

### `0x04` Ping

无载荷。客户端每次建立新的发送会话时首先发送 Ping；接收端收到后必须清除该远程端点的移动和滚动序号历史，并把原始 Ping 数据包返回给客户端。客户端只有在收到 magic、版本、序号和配对码都一致的响应后才显示连接成功。该消息也保留给后续存活检测和 RTT 测量。

## 接收规则

- magic、版本、配对码或长度不正确的数据包必须丢弃。
- 移动和滚动按远程 IP、远程端口和消息类型使用独立序号通道，迟到的数据包必须丢弃。
- 鼠标移动只关心最新状态，不重传历史数据。
- v2 将把按键、配对和配置移到可靠控制通道，并对数据包进行认证。
